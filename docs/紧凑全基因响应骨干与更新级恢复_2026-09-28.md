# 紧凑全基因响应骨干与更新级恢复

日期：2026-09-28。适用项目：`I:/科研/肺癌细胞凋亡-强化学习`。

## 结论和研究边界

默认响应骨干改为 `compact_full_gene`。这是一个新的响应模型候选，改变了速度场的函数族；不能把它称为旧基因 token/PAD 模型的数值等价优化，也不能凭速度认定预测精度更高。旧骨干以 `gene_token` 保留供单独实验。

本次保留完整 32,461 基因输入和输出、全基因空间中的条件流匹配（CFM）、完整区间 Heun 生成和最大均值差异（MMD）损失。没有用训练目标表达替代推理输入，也没有缩短生成区间或把两种强化学习方法合并。默认仍为 5 个响应成员、1000 epoch、FP32 模型运算，统计和耦合沿用原有精度策略。没有新增早停、奖励惩罚或数据标签。

当前验证证明程序可执行、恢复语义正确及有限工作量下的计算速度；完整训练、泛化精度、跨来源凋亡评价和 DA-AC/DLPA 的效果比较仍待正式实验。

## 为何更换骨干

旧骨干在全基因 token 表示上多次执行稀疏注意力和条件交互。MMD 还需要完整 ODE 生成及梯度重放，因此即使 GPU 持续忙碌，每个条件仍然很慢。只改变进度条、缓存或显存占用无法解决这个重复计算量。

新骨干把主要交互放在每个细胞的 256 维内部表示中，并用全基因投影接收输入、输出每个基因的速度。ODE 状态本身仍为 32,461 维，内部压缩属于模型容量选择，需要和旧模型及简单基线比较精度。

## 实际网络与数学定义

实现位于 `src/lung/models/compact.py`，选择入口是 `src/lung/models/factory.py`。设基因数为 G，内部宽度为 D，默认 G=32,461、D=256。冻结的训练集基因邻域生成稀疏行归一化矩阵 A，每行邻居的权重相等。

参考表达编码为：

$$
z_{\mathrm{ref}}=\operatorname{GELU}\left(\operatorname{LN}
\left(W_x x_{\mathrm{ref}}+W_A A x_{\mathrm{ref}}+b_x\right)\right).
$$

两个投影都接收完整基因轴。编码器返回一个 `[B,1,D]` 摘要 token 和 `[B,D]` 向量；下游状态、摘要和决策模块通过既有接口取得向量。这里的单个摘要 token 不表示单个基因。

药物指纹、剂量、实际处理时长、来源、细胞背景和协议仍经原有 `ConditionEncoder` 得到条件向量 q。生成时间 τ 通过原有 `GenerativeTimeEncoder` 得到 e(τ)。实际处理时长和生成时间是不同变量。

速度网络计算：

$$
c=P_c[z_{\mathrm{ref}};q;e(\tau)],\qquad h_0=P_x x_\tau+c,
$$

$$
h_{\ell+1}=h_\ell+\operatorname{MLP}_\ell\left(
\operatorname{LN}_\ell(h_\ell)\odot[1+\tanh(s_\ell(c))]+b_\ell(c)\right),
\quad \ell=0,\ldots,5,
$$

$$
[a;b]=P_o\operatorname{LN}(h_6),\qquad
v_\theta(x_\tau,\tau\mid x_{\mathrm{ref}},q)=\tanh(a)\odot x_\tau+b.
$$

每个残差块中的 MLP 为 D→2D→D，中间激活为 GELU。最终投影输出 2G 个数并分成两个 G 维向量，所以每个基因都有速度输出。对固定参考、条件和生成时间而言，跨基因交互经 D 维内部表示传递，另有逐基因的状态直连；这是一项明确的结构假设，不是精度保证。

CFM 继续沿用原有全基因路径、目标速度和损失。MMD 继续比较整批生成表达和真实目标分布，保留样本间交叉项。生成、端点导数和 ODE 梯度重放均调用同一新骨干；没有切断条件编码器或参考编码器的梯度。

`pad_layers` 在新骨干中表示紧凑残差块数。`encoder_layers`、`n_heads`、`query_chunk` 和 `checkpoint_attention` 为旧 token 骨干参数，不决定新骨干的层数或注意力行为。`checkpoint_blocks` 仍可控制紧凑残差块重算，当前默认关闭；完整 MMD 的 ODE 梯度重算机制保留。

## 默认配置与一键执行

在 PyCharm 选择 `F:/anaconda/envs/study/python.exe`，运行根目录 `train.py`，参数留空。启动表格显示 `响应骨干 compact_full_gene`。入口仍按依赖顺序执行 19 个任务，DA-AC 与 DLPA 分别训练、分别评估；时间分支也通过同一骨干工厂构造模型。

主要配置位置：

| 文件 | 当前设置及作用 |
|---|---|
| `configs/train.yaml` | `workflow: research_all`、`algorithm: both`、`epochs: 1000`、`device: cuda:0` |
| `configs/response.yaml` | `model.backbone: compact_full_gene`，控制响应模型和默认执行批量 |
| `configs/response_legacy.yaml` | 旧骨干的嵌套覆盖片段，供独立实验合并；它不是完整的独立训练配置 |

响应默认配置：

```yaml
members: 5
conditions_per_update: 8
ot_samples: 128
cfm_samples: 128
mmd_samples: 32
microbatch: 128
mmd_microbatch: 32
inference_microbatch: 128
train_ode_steps: 32
inference_ode_steps: 128
model:
  backbone: compact_full_gene
  n_genes: 32461
  d_model: 256
  pad_layers: 6
  checkpoint_blocks: false
```

微批扩大改变了执行分块；CFM 和 MMD 的逻辑样本数没有改变。新骨干消除了大量中间张量，显存占用可能下降，这不能单独用来判断训练速度或 GPU 是否工作。

需要运行旧骨干时，在单独实验配置的 `response` 节应用 `response_legacy.yaml` 中的覆盖值，或明确在 `response.yaml` 中改回 `gene_token` 及旧微批配置。两种骨干的权重不可互载。缺少 `backbone` 字段的历史模型配置按 `gene_token` 解释。

源码和配置身份改变后，自动续跑会创建新套件；旧文件仍保留。不要把旧套件 ID 强制用于新架构。准备阶段可使用仍有效的已有数据资产，但新响应权重需重新学习。

## 更新级保存与恢复

Tahoe 响应训练和时间响应训练都在每次完整 `optimizer.step()` 后原子写入 `last.pt`，保存模型、优化器、随机状态、当前 epoch 的条件顺序、下一条件位置、统计量和调度进度。

恢复规则：

1. 已完成并保存的参数更新跳过，不重新训练。
2. 中断在一个条件组内部时，丢弃未提交的部分梯度，从最近已保存的更新边界重新计算该组。
3. 一个 epoch 的全部训练更新已保存、但验证尚未提交时，恢复后先执行该 epoch 的验证，不重复整轮训练。
4. 时间分支继续使用原协议的 `fixed_final_epoch`，并检查数据范围、配置和产物身份。
5. 更新级检查点内的 `epoch` 仍表示完整提交的轮数；轮内位置记录在 `extra.update_resume` 中。仅看 epoch=0 不能断言没有已保存更新。

原有单行进度显示保留，避免多层进度条在 PyCharm 中反复追加行。进度文件位于各 run 日志目录；文件进度、参数更新计数和实际检查点共同判断训练是否前进。

## 有界性能测量

设备为 RTX 3080，使用现有 `study` 环境。测量脚本为 `scripts/benchmark_response_compute.py` 和 `scripts/profile_response_update.py`。所有本次短测与正式研究结果隔离。

| 工作量 | 输入与范围 | 实测耗时 |
|---|---|---:|
| CFM 前向和反传 | 全 32,461 维合成表达，128 样本 | 中位数约 0.0119 秒（2 次） |
| 完整 MMD 生成及反传 | 全维合成表达，32 样本，完整 32 步 Heun | 约 0.808 秒（1 次） |
| 一个完整参数更新 | 真实 T 数据，8 个条件，每条件 CFM128、MMD32，包括数据读取和耦合 | 49.037 秒 |
| 更新检查点写入 | 上述真实短测的模型和优化器等状态 | 0.654 秒 |
| 一个 V 条件诊断 | 128 步生成及原有验证计算 | 5.106 秒 |

真实更新前的数据打开耗时 0.677 秒，独立预热耗时 5.657 秒。模型参数数为 45,926,394，该短测的峰值 PyTorch 已分配显存约 0.90 GiB；它不包括桌面显示、驱动及其他进程占用。49.037 秒不包含上述单列预热、保存和 V 诊断。

真实短测仅完成一个参数更新。单个 V 条件的数值仅检查计算路径，不能证明收敛、精度或外部有效性。按该短测线性外推，644 条件的单成员训练部分仍约需 66 分钟/epoch，尚未计入完整验证和其他阶段；1000 epoch、5 成员及整个研究套件依旧是较大的实验。
