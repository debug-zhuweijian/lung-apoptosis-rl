# Ridge 数据汇总 GPU 优化

2026-09-26。对应用户截图中的第 2/15 个任务 `ridge`，进度为 `T full unique cells`。用户停止当前 PyCharm 运行后实施本次修改；正式训练仍由用户手动重新启动。

## 原因与实际修改

旧路径是：CPU 读取/解压 CSR → CPU 归一化、log1p 和标准化 → 生成完整的细胞×基因稠密矩阵 → 上传 GPU → float64 分组累加。因此已有 `device: cuda:0` 并不意味着这个阶段的大部分计算已在 GPU；这里此前遗漏了 CPU 预处理的迁移。

新路径是：单一 CPU 生产者读取/解压并检查合法样本 → 锁页内存中的稀疏数组异步上传 → GPU 逐细胞归一化、log1p、冻结标准化与 float64 分组累加 → 最终均值写出。

- 实现位于 [ridge_stream_cuda.py](../src/lung/engine/ridge_stream_cuda.py)，由 [stream_means](../src/lung/engine/pilot_ridge_data.py) 的 CUDA 分支自动调用。
- 只搬运稀疏计数及索引，不在 CPU 生成每批完整稠密表达矩阵；最终条件均值仍保留全部 32,461 个基因。
- 复用有界有序预取，唯一读取线程拥有原两分片缓存；读盘与 GPU 运算可以重叠。异常时关闭预取线程，不遗留后台读取。
- 不改变冻结归一化参数、T/V 划分、唯一细胞计数、对照加权规则、Ridge 正则候选或 float64 求解。
- 进度条增加实际后端标识：`T full unique cells [CUDA sparse FP64]`，V 阶段同理。
- 实测增大批量没有进一步加速，`configs/pilot_ridge.yaml` 的 `stream_batch_size: 512` 保留。无需用户另改参数。

## 数值定义

保留原顺序：float64 库大小和 log1p → float64 冻结标准化 → float32 坐标舍入 → float64 汇总。没有启用 FP16、BF16、TF32，也没有通过抽样或少用基因提速。

记标准化坐标为 $z_{ig}$，结构零对应 $z_{0g}=\operatorname{float32}(-\mu_g/s_g)$。每个条件池的均值使用恒等式：

$$
\bar z_g=\frac{N z_{0g}+\sum_{i:c_{ig}\ne0}(z_{ig}-z_{0g})}{N}.
$$

每个非零坐标先按原定义舍入为 float32，再提升到 float64 计算差值和累加。这样不必展开所有结构零。GPU 与 CPU 的归约、log1p 不承诺在所有输入上位级一致，须按数值测试核对。

审查发现重复 CSR 坐标自动合并会改变旧读取器的冻结坐标定义，已改为明确拒绝 `DUPLICATE_CSR_COORDINATES`；未排序但不重复的合法 CSR 在副本排序后处理。没有自动修改源数据或旧归一化定义。

## 实际性能与结果

使用本机 RTX 3080，取同一组 **8,192 行真实 T/fit 数据、46 个条件池、20 个源分片、全部 32,461 基因**。每种方法各运行 3 次，交替顺序，GPU 预热并同步；每轮独立使用新的两分片读取缓存。

| 批量 | 旧 CPU 归一化＋GPU 汇总中位耗时 | 新 GPU 稀疏路径中位耗时 | 倍率 |
|---|---:|---:|---:|
| 512 | 4.765590 s | 0.679277 s | 7.02× |
| 2048 | 4.487851 s | 0.701860 s | 6.39× |

12 次试次的均值形状均为 `(46, 32461)`，最大绝对差、所报告的非零坐标相对差及近零坐标差均为 **0**。输入均为无重复的 canonical CSR；执行前后被测源码哈希一致。

新路径 512 批量的 PyTorch 峰值已分配显存为 45.69 MiB，2048 为 141.52 MiB；这是该子集进程内测量，不是整个训练或显卡总占用。新路径剩余时间主要消耗在读取/解压等待，GPU 不会因此持续显示 100% 利用率。

计时包含分片读取、准备、归一化、传输、汇总和最终均值拷回；共享元数据加载/校验另计 1.031 s。操作系统文件缓存未清空，生产者与 GPU 时间存在重叠，分项时间不能直接相加。此结果只证明这个前缀子集的汇总路径提速，不能把 7.02× 当作完整 15 任务训练或全量冷盘读取的加速承诺。未运行真实 Ridge 拟合或其他真实正式模型训练。

原始证据：[benchmark-final.json](../.omo/evidence/ridge-gpu-20260926/benchmark-final.json)、[实际输出](../.omo/evidence/ridge-gpu-20260926/benchmark-final.log)。小型基准入口为 [benchmark_ridge_stream.py](../scripts/benchmark_ridge_stream.py)，限制最多 65,536 行，只读 fit 表达，结果只写证据目录。
