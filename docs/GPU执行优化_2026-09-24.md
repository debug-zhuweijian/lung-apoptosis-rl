# GPU 执行优化与验证

本轮范围：用户停止 PyCharm 训练后，要求将可并行运算尽量放到 RTX 3080，加快准备、响应模型训练及强化学习中的世界模型推演。优化执行方式，不改变研究目标、监督、奖励、完整共同基因轴或数据划分。正式训练仍由用户启动。

## 生效配置与运行方式

直接运行项目根 `train.py`。解释器仍为 `F:/anaconda/envs/study/python.exe`；默认 `cuda:0`、response 阶段、1000 epoch、5 个响应成员。`configs/response.yaml` 现在设置：

| 参数 | 值 | 含义 |
|---|---:|---|
| microbatch | 2 | CFM 每次前后向的细胞数 |
| mmd_microbatch | 2 | MMD 完整 ODE 的生成与梯度重算微批 |
| inference_microbatch | 2 | 世界模型推演、公共编码及辅助特征准备微批 |
| model.query_chunk | 4096 | 稀疏注意力每次处理的查询基因数 |

这不是把每条件样本数改成 2：仍为 128 个 CFM 对、32 个 MMD 生成和实测样本、8 条件等权累积。训练 Heun 32 步及完整梯度、5 个模型、FP32 神经计算、FP64 统计/OT 和时间特征保持原定义；未启用 AMP、TF32 或减少基因/积分步数。

本次源代码及配置已变化，重新点击运行会创建新的 run。先前运行停在预处理，没有可续接的模型 epoch；使用已验证的缓存继续准备即可，不要把旧 run 的配置当成新版配置。旧日志、原始数据、划分和缓存保留。

## 预处理路径

`train.py → open_data → prepare_training` 显式传入训练设备。CUDA 不可用时明确报错，不悄悄切换 CPU。独立准备脚本也支持 `--device cuda:0` 或显式 `--device cpu`，不启动模型训练。

1. 校验现有 `fit_cache`；已完成的压缩缓存不再从原始数据重新制作。
2. 第一次 CUDA 准备将 T 缓存解压成 `fit_cache_stream` 的无损、可内存映射数组。只保存稀疏值、索引、行指针和权重；数据分块读取，不要求将全表达装进内存。抽查外推约需 18 GB 额外磁盘，实际以生成文件为准。
3. 来源/条件/细胞等权的均值和方差在 GPU 以 FP64 计算。旧统计文件首次核对数值后保持原字节，再写来源绑定和哈希回执；后续可复用。
4. 基因图使用 FP64 CUDA 稀疏矩阵乘法 `Xᵀ @ (w X_block)` 并原位累加。显存允许时一次算 4096 个查询基因；原 128 个基因的磁盘保存粒度保留。32461 轴需要约 8 次主矩阵扫描，显存不足时自动减小计算块；不会把基因数或样本数减小。
5. GPU 进行相关系数计算及按 ID 预排序的稳定邻居排序。对接近并列的排名，仅将可能入选的候选送回原 CPU 算式复核；不使用 epsilon 合并平局。真正零方差仍定义相关为 0。
6. 固定 MMD 带宽仍按 SHA 选每条件 128 个细胞、全局 4096 对。入选表达按原始分片集中读取一次，暂存于最多约 1.06 GB 的临时映射文件；全基因距离由 GPU FP64 分块计算。成功或普通异常退出时释放并清理本次临时文件。

CPU 负责文件读取、解压、哈希、元数据和必要的近似并列复核。这些步骤不是神经网络训练，也不能用显存占用代表训练吞吐。

缓存回执绑定来源、基因轴、统计、权重、分片位置及计算规则，并校验内容哈希。新版 CUDA 块不能跨排序策略混用；中断只复用完整发布的块。已有旧 CPU 图块首次记录为 `legacy_structure_adopted`，表示兼容接续已知历史产物，不表示本轮重新执行过该块的全 T 计算。旧 CPU 后端原有恢复检查不等于新版 CUDA 回执检查。

## 排名复核的数值依据

这里是执行层的浮点误差判据，不是生物学保证。固定同一组均值和标准差，输入为有限非负的 log 表达、权重非负；在正常浮点范围内，以 FP64 单位舍入误差 `u=eps/2`、实际细胞行数加分块数和常数余量为 N，使用 `gamma=N*u/(1-N*u)` 构造保守相关误差界。代码使用总行数，而不假定 cuSPARSE 内部具体的累加树。

令每行误差界为 E。前 K+1 个绝对相关评分的所有相邻间隔均大于 2E 时，入选边界和内部顺序均无歧义；否则保留 `score >= kth_score - 2E` 的候选，以原 CPU 数值重新排名。低于该门槛的候选，其上界低于至少 K 个候选的下界；等号保留。该界只用于决定哪些数值需要复核，不用于把不同相关系数认定相同。CPU 候选乘法按最多 64 个查询共享候选并集，避免对每个歧义查询重算全基因矩阵。

数学估计量不变，但跨 CPU/GPU 规约不能泛称逐位相同。零分并列、近常量消去、重复列、候选裁剪和完整真实小样本图均有独立测试。

## 正式训练和世界模型

- 增大查询分块，降低每层稀疏注意力的 Python 循环和 CUDA 小任务数量。softmax 仍沿同一 33 邻居计算，不构造完整基因×基因注意力。
- MMD 仍先计算整批端点的完整三项损失及端点导数，再按微批重放同一完整 ODE。固定输入、噪声下与原生整图梯度比较通过。
- 外部时间输入继续校验；内部 Heun 和 `torch.rand` 生成的合法时间走可信路径。32 步轨迹去掉 192 次重复标量读取，最终非有限值检查保留。
- 终端子阶段刷新节流为 0.5 秒，阶段变化和完成仍立即显示。
- 世界模型按微批推演，每个细胞保留原 `stream_seed` 和 `(1,G)` 噪声采样，再拼批；模型成员、前缀、时间及奖励不变。
- 世界模型表达与特征直接保留 GPU Tensor，去掉大矩阵 GPU→CPU→NumPy→GPU 往返。辅助缓存仍按原格式返回 CPU。
- 推理微批参数进入世界版本、辅助缓存和校准审计绑定，不混用不同执行设置的旧结果。

## 进度显示与重启

准备阶段开始即出现进度，缓存校验、映射缓存、统计、每个GPU图块、排名复核、保存和带宽分开显示。旧阶段到100%便关闭，不再把后续等待累计到旧进度条。

`run_manifest.json` 保存独立的 `preparation` 快照；TensorBoard 在 `preparation/` 下显示准备进度，至少每5秒写入一次，阶段边界立即刷新。这不是模型epoch。重新运行后选择新run；模型开始后观察 `response/member_1/optimizer_step/` 和对应epoch指标。
