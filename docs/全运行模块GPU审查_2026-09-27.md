## 1. 结论与本轮范围

**当前实现尚未达到“全流程尽可能利用 GPU”的要求。** 细胞/药物/剂量/时间编码器、条件流匹配、主要神经网络的反向传播、DA-AC 的 Actor/Critic、DLPA 的提议网络和蒸馏已经使用配置设备；但数据归一化、时间分支的部分数值计算、重复模型加载、逐样本调用和设备间往返仍存在明显优化空间。

上一轮完成的 Ridge 流式汇总 CUDA 优化只覆盖 Ridge 路径，不能代表所有读取器、辅助模块和决策评估都已经优化。

本轮覆盖默认 `research_all` 的 **15/15 个任务节点及其主要数值调用链**，补查 `test.py`、监控、断点保存和可选真实终点模块。这里的“覆盖”指静态调用链审查，**不表示 15 个正式任务已经在 GPU 上完成全量训练或性能测量**。

本轮交付审查、具体改造方案与只读运行探针；没有修改生产源码、配置、原始数据或已有权重。用户仍通过 PyCharm 手动启动正式训练。当前检查未发现 `train.py`、`test.py` 或 Ridge 训练进程。

## 4. 主要发现与可实施修改

以下 P1/P2 是工程修改优先级，**不是全量 profiling 得到的耗时排名**，也不等于模型科学正确性失败。

### P1-A：时间预测器在每次调用中重新读取与构建冻结网络

证据：`timecourse/response.py:152-174` 每成员调用 `load_checkpoint`、构建 `ResponseModel`、加载状态并转入设备；`timecourse/auxiliary.py:166-172` 每次 `infer` 都 `torch.load` 并重建网络；`timecourse/nested.py:205-210` 将这些函数串在每一次预测内。本轮两次预测实际产生 10 次文件加载。

建议在 `FrozenTimePredictor` 初始化时建立绑定 checkpoint 内容、数据坐标和设备的冻结模型集合；显存不足时采用有界驻留/成员分块，而非无条件把全部网络同时放入显存。折间或权重变化必须更换缓存身份。Tahoe 的 `BiologicalWorld` 已经在初始化时加载成员，不应误报它也在每次评分重新加载。

验收：同一实例重复调用不再重复反序列化同一权重；数值输出、门控选择、U 上界及源文件哈希符合原契约；权重变化不会误用旧缓存。测试 CPU/GPU 两种设备及显存上限。

### P1-B：共享读取器仍在 CPU 归一化，时间分支额外保留 CPU 数值链

证据：`data/reader.py:142` 调用 `preprocess.standardized`；`timecourse/data.py:158` 的 `_read` 最终也调用 CPU 标准化。`engine/response.py:42` 再复制 NumPy 数组并传入设备。Ridge 的新 helper 没有覆盖这些调用。

时间分支还有已复现的 `nested_features.py:13` CPU 投影和 `auxiliary.py:50-53` CPU RBF 核。`timecourse/preparation.py:141` 固定调用 CPU `weighted_moments`；`state_proxy.py:12` 的坐标转换及 `decision_world.py:77` 的表达统计/投影为 NumPy。

建议增加保持同一基因轴与采样结果的设备表达读取路径：CPU 负责解压与索引，有界预取稀疏批次，GPU 负责行总量、log、标准化和所需稠密化。**Ridge 的群体均值累加器不能直接替代保留逐细胞表达的训练读取器。** P→投影→Pool/B→K→U→状态头之间尽量保留设备张量，只在报告或持久化边界导出数组。时间 MMD 分块在 GPU 归约，保留现有 FP64 输入与核定义。

验收：零库大小、稀疏重复坐标、基因重排、实际采样行、源/条件权重、FP32 舍入点、FP64 汇总均与旧契约对照；CPU/GPU 最大绝对/相对误差记录完整。不得只比较最终平均损失。

### P1-C：状态头和辅助网络的批大小是梯度累积单位数，未形成批量前向

证据：`engine/auxiliary.py:120-129` 在一个 selected batch 内逐行执行 `loss_function` 和 `backward`；`train_state` 在 `:289-293` 对一个潜变量产生 `[1,3]` logits。`state_batch: 64` 当前不是一次计算 64 个样本的分类前向。每行还有 `float(loss.detach())` 主机同步。

建议先对形状固定的状态头和紧凑辅助特征做真正组批；原来的 64 个独立单位仍组成同一有效批次，保持一次优化器更新和固定全局权重。对变长群体使用分桶/掩码或有界微批，不为追求单个大 batch 丢掉独立群体边界。

验收：固定输入/顺序/权重，比较逐单位累积与批量计算的每项损失、梯度和一次参数更新；核对尾批分母及断点恢复。不能通过改变有效 batch 或学习率来掩盖执行优化差异。

### P1-D：Tahoe 反向模型训练会反复读取并上传不需要的大表达张量

证据：`engine/residuals.py:88-90` 读取整个预测文件，并将其中所有 Tensor 移到设备；`:101-103` 的 B 损失只需要 `observed_population`、`condition`、`reference_mean`。生成该文件时 `:54-70` 还包含逐条件加载部分成员及逐细胞 CPU/GPU 往返。

建议按任务拆分不可变紧凑特征索引和大群体表达；B/U 只加载所需字段，K 以有界预取读取所需完整表达；同一折/同一源版本复用冻结模型与条件编码。读取后再过滤字段只能减少上传，若需消除磁盘重复反序列化，还应采用独立紧凑缓存或有界主存缓存。

验收：B/U 的 GPU 输入不包含无用完整表达；角色权限、文件身份和训练目标不变；在显存/主存预算下测每步读取字节和耗时。不能把全量预测数据一次塞入 10 GB 显存。

### P1-E：DA-AC / DLPA / 独立比较的世界模型评分仍是串行重复推演

证据：`engine/world.py:272-284` 每 seed 调用 `score_one`，每次输出 Python float；`rl/environment.py:77` 强制结果回 CPU FP64。`rl/evaluation.py:43-52` 的 `block_size` 只拆种子列表，没有将不同重复合成一次 GPU 推演。DLPA 在 `rl/dlpa.py:159-162` 逐候选调用该接口。Phi 的参考补全目标也反复走同类评分路径。

建议先建立统一的、有界候选×独立重复评分接口，把设备端标量累计到批次结束后再导出；再分批执行多个独立群体的 P/K/状态头。必须保留独立群体的统计、状态识别和 U/K 特征，不能把多个重复的细胞混成一个群体。各任务继续使用独立的规划/训练选择/最终审计随机流。

另一个较小而明确的修复是 `rl/environment.py:175-184`：冻结 Actor 候选生成只缓存 state，没有缓存同一 prefix 的概率。单次曝光的默认 256 次提案会对同一个空 prefix 重复运行 Actor。可在**同一次冻结生成调用**中缓存概率，同时保留原 CPU multinomial 的次数、顺序及 RNG；不可跨 Actor 更新复用。

验收：同 seed 的候选集合和 RNG 终态；批量/原串行评分的均值、标准误、奖励、候选排序及近并列情况；E 不参与训练或重选；恢复后的回放和策略更新计数一致。不能通过减少粒子数、评分重复数或候选数提速。

### P2-A：已有 GPU 路径中，部分调用仍硬编码微批 1 或频繁搬运模型

`engine/residuals.py:56`、`engine/evaluate.py:35`、`engine/diagnostics.py:49` 的逐细胞推演和 `timecourse/state_proxy.py:48` 的 `batch_size=1` 应统一到显存有界的冻结推理接口。`pilot_response.py:209-220` 对每个条件执行 `model.to(device)` / `model.cpu()`，虽然保证小显存，但存在重复搬运。

不能直接把全基因 Transformer 的 batch 从 2 改为 64。应在真实 32,461 基因、5 个成员和实际 ODE 步数下测可容纳的微批，固定原采样与噪声；执行分块不改变数学样本数。现有完整 ODE 的梯度检查点和注意力分块有显存用途，不能直接关闭。

### P2-B：RL 离散规划表和批次组装仍在 CPU

DLPA `ConditionalTable` 在 `rl/dlpa.py:37-38` 明确使用 CPU double，精英统计/更新也在 CPU；DA-AC 的动作抽样把概率回传 CPU。`PrivateHistory.forward` 在 `rl/networks.py:49-60` 逐状态传输，再分别运行私有历史编码。

先将固定原始特征/掩码按批组装，一次传输；Actor、Critic 和 target 仍用各自私有历史编码器。当前默认 `single_exposure_only` 多为空历史，不能夸大 GRU 批化的实际收益。保留 CPU 回放容量与抽样顺序，避免把 250,000 条回放全部常驻显存。

规划表是否迁到 GPU 应按完整耗时决定。小条件表使用 CPU 可能比往返 GPU 更快；若改用 GPU 抽样，同一 seed 通常不能视为原 CPU RNG 的相同序列，必须记录新执行版本并重新验证，而非宣称位级复现。

### P2-C：同步检查、日志和完整保存可能阻塞供数

`models/objectives.py:41-42` 的 OT 收敛循环逐次 `.item()`；CFM 和辅助训练逐微批导出损失；`monitoring/run.py:187-203` 每次 record 刷新 CSV/TensorBoard 并写状态，epoch 结束还重新读指标绘图。`engine/decision.py:251-257` 每次 DLPA 蒸馏更新保存完整 learner，包含教师集；DA-AC 单回合保存包含回放。

建议分别计时后：合并批次指标导出；把同 epoch 不变的教师数据存为一次不可变快照，后续检查点引用其身份；日志刷新和绘图适当节流。若调整恢复粒度，须显式更新契约；后台保存必须先获得一致的不可变参数/优化器/RNG 快照。OT 收敛条件和非有限值检查不能为加速直接删除。

## 5. 推荐实施顺序与验收

| 顺序 | 修改范围 | 完成标准 |
| --- | --- | --- |
| A | 冻结时间 P/B/K/U 缓存；同一冻结 Actor 的 prefix 概率缓存 | 重复加载/前向次数下降；原输出、RNG、权限和版本验证通过 |
| B | 时间投影、MMD、坐标转换、特征统计的设备张量链；共享读取器 CUDA 归一化 | 设备探针证明大数值操作在 CUDA；CPU/GPU 数值对照通过；无额外角色数据读取 |
| C | 状态头真正组批；B/U 紧凑缓存；K 预取；统一冻结微批推理 | 相同有效批次的一步梯度/参数更新对照；真实全基因数据吞吐和显存测量 |
| D | 世界模型多重复/多候选批量评分，覆盖 Phi、DA-AC、DLPA、时间分支和 test | 群体边界、各随机流、均值/标准误/排序、独立 E 审计契约通过 |
| E | DLPA 条件表/私有历史批化、日志/检查点节流 | 用实测决定迁移；断点恢复和完整套件合成回归通过 |

每一阶段用同一硬件、同一数据/种子/数值精度测端到端耗时，记录 CPU 准备、磁盘读取、H2D/D2H、GPU 数值、保存耗时及峰值 allocated/reserved VRAM。包含暖机和多次测量；冷/热文件缓存分别标明。不能仅凭 GPU 占用图变高就判定提速。

先改执行和数据流，再考虑 `torch.compile` 等额外工程优化；当前热点不能仅靠打开一个 CUDA 或编译配置消除。

## 6. 精度与研究契约

- 保留完整 32,461 基因、现有 FP64 统计/OT/关键归约和 FP32 神经网络规则；不为本轮速度目标启用 FP16/BF16/TF32。
- 保留 5 个响应成员、有效样本数、ODE 精度诊断、群体规模、候选数和独立重复数；微批调整仅改变执行分块。
